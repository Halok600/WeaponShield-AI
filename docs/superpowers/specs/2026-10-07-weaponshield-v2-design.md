# WeaponShield AI v2 — Design Spec

**Date:** 2026-10-07
**Status:** Approved in brainstorming, pending written-spec review
**Goal:** Rebuild WeaponShield AI into a recruiter-grade portfolio project: a more accurate weapon + person detector, running entirely in the visitor's browser (zero hosting cost, never "offline"), with a polished console UI, an honest model card, and an optional Python edge tool for real RTSP cameras.

---

## 1. Why v2

| Problem in v1 | Evidence | v2 answer |
|---|---|---|
| Live demo is dead | `weapon-sheild-ai.vercel.app` calls an expired ngrok URL; every visitor sees "Backend offline" (CORS error on `/health`) | No backend: inference runs in the browser via ONNX Runtime Web |
| No free always-on GPU server exists | Colab needs manual restarts; Render free tier OOMs / cold-starts | Same — the visitor's device is the compute |
| Knife is weak | Knife mAP50 0.636, recall 0.592 | Open Images V7 knife/dagger boxes + targeted augmentation |
| False positives on phones/tablets | Activity log, Bug 5 | Hard-negative images with people holding look-alike objects |
| Domain gap on CCTV footage | Activity log, Phase 3 | CCTV-style training augmentation (blur, JPEG, low light, noise) |
| Presentation | No tracking, no person context, debugging sliders exposed as features | Tracking, ARMED-person logic, event timeline, demo gallery, model card |

**Reference point.** The LinkedIn/Kaggle project (`uzairahmad1434/gun-detection-yolov11n`) reports 0.995 mAP50, but its notebook sets `val` to the training images (`Using 1860 train, 1860 val images`), so that number measures memorisation. It is actually YOLO26n on ~1,860 frames from a few webcam recordings. What it does well is presentation (person + gun boxes, ARMED flag, tracking trails, live stats). v2 adopts that presentation on top of an honestly evaluated, broader model.

## 2. Model and data

### 2.1 Classes
`0 person · 1 pistol · 2 rifle · 3 knife`

Source-class mapping: Handgun/Pistol → pistol; Rifle/Shotgun/Machine gun → rifle; Knife/Kitchen knife/Dagger → knife; Person → person.

### 2.2 Data sources (all free)
1. **Roboflow Universe weapon datasets** — re-downloaded via a cleaned-up `training/data/download_roboflow.py` (successor of v1's `download_roboflow_dataset.py`), remapped to the class list above.
2. **Open Images V7** (via FiftyOne) — Handgun, Rifle, Shotgun, Knife, Kitchen knife, Dagger, plus Person boxes. Licence: annotations CC BY 4.0, images CC BY 2.0; attribution listed in the model card.
3. **Hard negatives** — Open Images images containing Mobile phone, Tablet computer, Remote control, Drill, Hair dryer, Umbrella, Camera, Flashlight; only their Person boxes are kept (all other objects are background).
4. **Person pseudo-labels** — weapon datasets do not label people. A pretrained YOLO26x (COCO) auto-labels persons at conf ≥ 0.5 on every weapon image that lacks person boxes, so the model is never taught "person = background".

### 2.3 Hygiene
- Perceptual-hash (pHash) deduplication across all sources before splitting.
- **Group-aware split** (train 80 / val 10 / test 10): images that share a source video/sequence (detected from filename patterns such as `*_mp4-0042_jpg*`, plus pHash clusters) always land in the same split.
- The test split is never used for model selection, threshold tuning, or early stopping.
- A separate **hard-negative eval set** (~500 images, zero weapons) measures false-positive rate.
- Dataset stats (images and instances per class per split, per source) are generated by script and published.

### 2.4 Training
- Platform: Kaggle Notebooks, free GPU (T4, ~30 h/week quota). Notebook lives in `training/notebooks/`.
- Candidates: YOLO26n and YOLO26s at imgsz 640, ~120 epochs, patience 30, default Ultralytics augmentation plus Albumentations: MotionBlur, ImageCompression (quality 30–90), RandomBrightnessContrast/low-light gamma, GaussNoise, Downscale.
- Export: `model.export(format="onnx", nms=False, opset=17)` → end-to-end output `(1, 300, 6)` = `[x1, y1, x2, y2, conf, class_id]` in letterboxed 640 coordinates. FP16 variant also exported and compared.
- Selection rule: pick the largest candidate that sustains ≥ 15 FPS (WebGPU) on the developer laptop (RTX 3050 laptop, Chrome) and ≥ 5 FPS on WASM; otherwise fall back to n.

### 2.5 Targets (aims, measured honestly — not guarantees)
- Weapons-only mAP50 on the held-out test > 0.833 (v1 baseline).
- Knife mAP50 ≥ 0.75.
- Hard-negative set: false-positive images reported at the shipped "Balanced" threshold.

### 2.6 Model card (`/model` page + `docs/model-card.md`)
Per-class P/R/mAP50/mAP50-95, PR curves, confusion matrix, hard-negative FP rate, browser FPS (WebGPU/WASM), dataset composition and licences, a failure gallery, intended use and limitations. The same artefacts are published on a Hugging Face Hub model repo.

### 2.7 Licence
Ultralytics YOLO is AGPL-3.0; the repo licence changes from MIT to AGPL-3.0.

## 3. Web app architecture (`web/`)

### 3.1 Stack
Vite, React 19, TypeScript (strict), Tailwind CSS v4, shadcn/ui (Radix), Motion, Lucide, Recharts, React Router, onnxruntime-web, Vitest, Playwright. Static build, deployed on Vercel.

### 3.2 Pipeline
```
source (webcam | <video> | image) → ImageBitmap (transferred) → Web Worker
  worker: letterbox to 640 on OffscreenCanvas → Float32 NCHW tensor
        → onnxruntime-web (WebGPU EP, fallback WASM SIMD+threads)
        → (300,6) → conf filter → un-letterbox → Detection[]
  main:  tracker → threat engine → canvas overlay + UI state
```
- **Backpressure:** at most one frame in flight; new frames are dropped while the worker is busy, so latency never accumulates.
- WASM threads require cross-origin isolation: `vercel.json` sets `Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Embedder-Policy: require-corp`.

### 3.3 `web/src/core/` (framework-free, unit-tested)
- `types.ts` — `Detection {cls, conf, box}`, `Track`, `ThreatEvent`.
- `preprocess.ts` — letterbox geometry + tensor fill; returns `{tensor, scale, padX, padY}`.
- `postprocess.ts` — decode `(300,6)`, threshold per class, map back to source pixels, clamp.
- `tracker.ts` — ByteTrack-lite: constant-velocity Kalman filter per track, two-stage IoU association (high-conf then low-conf detections), track birth after 2 hits, death after 30 missed frames. Per track: class by majority vote over history, EMA confidence, trail of last 30 centres.
- `threat.ts`:
  - A weapon track is **confirmed** when it was matched in ≥ K of the last N processed frames.
  - A person track is **ARMED** when a confirmed weapon track's centre lies inside the person box expanded by 20% on each side (handles guns held away from the body); the nearest person wins if several qualify.
  - Emits `ThreatEvent {id, cls, personTrackId?, startMs, endMs, maxConf, snapshot}`; an event ends after the weapon track is lost for 2 s.
- `presets.ts` — Low / Balanced / High → `{confByClass, K, N}`; values chosen from the model card's PR curves on the validation split.
- `worker.ts` + `engine.ts` — loads the model once, reports the backend in use (webgpu | wasm) and per-frame inference ms.

### 3.4 Modes
- **Live:** `getUserMedia`, camera picker, mirrored preview toggle.
- **Video:** frames driven by `requestVideoFrameCallback`; event timeline with thumbnails; export annotated clip (canvas `captureStream` + MediaRecorder → WebM) and report (JSON/CSV).
- **Image:** single pass, stricter preset; download annotated PNG.

### 3.5 Model delivery
`.onnx` served same-origin from `web/public/models/`; cached by a service worker (Workbox via `vite-plugin-pwa`) so repeat visits load instantly and work offline. A download progress bar is shown on first load. Hard limit: the shipped model file ≤ 25 MB.

### 3.6 Development before the weapons model exists
The pipeline is built and tested end-to-end against the stock YOLO26n COCO model exported the same way (person class only), then swapped for the trained model by changing one config entry (`web/src/config/model.ts`: url, class names, input size).

## 4. Frontend and UX

**Look:** dark "security operations console" — near-black slate surfaces, subtle grid, monospace numerals; one signal colour per meaning: red = weapon, green = person, amber = ARMED. Light theme supported. Responsive down to 360 px (side panel stacks below the stage).

**Pages**
1. **Landing `/`** — hero autoplays detection on a bundled demo clip (no permission prompt, no upload); metrics strip (test mAP, live FPS on this device, "0 bytes uploaded"); "how it works" diagram; CTAs to Console, Model card, GitHub.
2. **Console `/console`** — tabs Live / Video / Image.
   - Stage: video + canvas overlay (boxes, track IDs, trails, ARMED tag).
   - Side panel: persons / weapons / armed counts, FPS, inference ms, backend badge (WebGPU/WASM), sensitivity preset.
   - Alerts: full-width banner + sound + Notification API, 10 s cooldown per event.
   - Event timeline: thumbnail cards (click to seek in Video mode), export JSON/CSV.
   - Demo gallery: 3–4 clips with permissive licences (Pexels/Pixabay), attributions shown.
3. **Model card `/model`** — section 2.6 content, interactive PR curves.
4. **How it works `/architecture`** — pipeline diagram, browser-inference rationale, edge tool.

**Details:** WebGPU capability check with a clear fallback notice; keyboard shortcuts (Space pause, S snapshot); privacy note ("frames never leave your device"); Lighthouse ≥ 90 on performance, accessibility, best practices.

## 5. Edge tool (`edge/`)

```
weaponshield-edge --source rtsp://user:pass@host/stream1 --sensitivity balanced --telegram [--show]
```
- `--source` accepts RTSP/HTTP URLs, a webcam index, or a video file.
- Reader thread keeps only the latest frame; auto-reconnect with backoff on stream loss.
- onnxruntime (CPU default, CUDA provider if available) running the same `.onnx` as the web app.
- `tracker.py` / `threat.py` port `web/src/core` logic. Parity is enforced by shared JSON fixtures in `fixtures/parity/` (detections in → expected events out) tested by both Vitest and pytest.
- Telegram alerts: annotated snapshot + caption (`ARMED person · pistol 0.87 · cam1 · 14:02:11`), one per new event plus cooldown. Bot token/chat ID from the user's own `.env`.
- Output: `events.jsonl` + snapshot JPEGs.
- Packaging: `pyproject.toml` (`pip install -e edge/`), small Docker image. Config via `.env` or YAML.
- Tests: pytest using a short sample video as the source, Telegram mocked. No web UI, no database.

## 6. Scope removed from v1

Tag the current `main` as `v1-legacy` before removal.

| Removed | Reason |
|---|---|
| `backend/`, `app.py`, `Dockerfile`, `render.yaml`, root `requirements.txt` | Replaced by in-browser inference |
| Colab + ngrok hosting | Root cause of the dead live site |
| Resend email alerts to a fixed operator address | Spam/abuse risk on a public demo |
| PyTorch/ONNX dual engine | Single ONNX engine everywhere |
| CCTV noise/blur/pixelate toggles, frame-skip and raw confidence sliders | Debug knobs; robustness moves to training |
| Server-side H.264 encoding, in-memory job store, `print()` debugging | No longer needed |
| `model/best.pt`, `model/best.onnx` in git | Model lives in `web/public/models/` (build artefact, ≤ 25 MB) and on HF Hub. Old history is kept (no rewrite) |
| `PROJECT_ACTIVITY_LOG.md` | Replaced by `docs/decisions.md` (decisions and lessons learned) |
| Old `frontend/` | Replaced by `web/` |

Kept as ideas: multi-frame confirmation (now per track), per-mode thresholds (now presets), three weapon classes, dataset merge/relabel lessons.

## 7. Repository, CI, deploy

```
web/        Vite React TS app (src/core = inference, tracker, threat engine)
training/   data scripts (download, map, dedup, split, autolabel, stats) + Kaggle notebook
edge/       Python RTSP tool
fixtures/   cross-language parity fixtures
docs/       model card, architecture, decisions, specs, plans
```
- **CI (GitHub Actions):** `web` — eslint, `tsc --noEmit`, Vitest, build, Playwright smoke test (landing loads, demo clip draws ≥ 1 box). `edge` — ruff, pytest. `training` — ruff + unit tests for mapping/dedup/split.
- **Deploy:** Vercel project root set to `web/`; production on push to `main`. Project/domain renamed to the correct spelling `weaponshield-ai.vercel.app` (or closest available); the old URL stops working.
- **Git:** all work on branch `v2`, merged to `main` when the new site is live-ready. Every commit and PR under the owner's identity only — no co-author trailers or generated-by lines.

## 8. Testing strategy
- **Core (Vitest):** letterbox round-trip geometry; postprocess decoding on a recorded real model output; tracker ID stability on synthetic trajectories (crossing, occlusion); threat K-of-N and ARMED containment cases; preset mapping.
- **Model golden test:** for 5 fixed images, browser-pipeline detections match Ultralytics Python predictions (IoU ≥ 0.95, |Δconf| ≤ 0.02).
- **Parity (Vitest + pytest):** shared fixtures → identical events.
- **E2E (Playwright, Chromium):** landing autoplay draws boxes; image upload returns detections; WASM fallback path works with WebGPU disabled.
- **Training scripts (pytest):** class mapping, dedup, and group split never leak a group across splits.

## 9. Error handling
- Model download failure → retry button + message; service-worker cache used when offline.
- WebGPU unavailable or fails at session creation → automatic WASM fallback, badge shows "WASM".
- Camera permission denied / no camera → explanatory empty state with a link to the demo gallery.
- Unsupported video codec → message suggesting MP4 (H.264).
- Edge: stream drop → reconnect with exponential backoff; Telegram failure → logged, event still written to JSONL.

## 10. Delivery phases
0. **Reset:** tag `v1-legacy`, branch `v2`, new layout, AGPL licence, remove v1 scope.
1. **Data + training:** scripts, Kaggle notebook, train n/s, evaluate, export ONNX, model card data.
2. **Browser core:** worker, engine, pre/postprocess, tracker, threat engine — built against stock YOLO26n first.
3. **Frontend:** landing, console (3 modes), model card, architecture page, demo gallery.
4. **Edge tool:** CLI, Telegram, Docker, parity tests.
5. **Ship + showcase:** swap in trained model, Vercel rename, README with demo GIF and honest metrics, HF Hub model repo, merge `v2` → `main`.

Phases 1 and 2–3 run in parallel (training runs on Kaggle while the web app is built against the stock model).

## 11. Out of scope
User accounts, a server-side API, multi-camera dashboards, cloud storage of footage, mobile apps, segmentation/pose models.
